One-command seeded development workflow

Drive the lifecycle of a single npm run dev over real PostgreSQL and MinIO. Press anything in any order: legal actions advance the workflow, illegal ones are refused with the message a developer would actually see. Then run the walkthroughs for the awkward cases.

Question being prototyped: what concrete one-command development workflow makes the corrected baseline immediately testable end to end through a browser? This models the command shape around the seed and reset contract and the five-step readiness gate settled in Define the real PostgreSQL and MinIO persistence baseline, replacing the undocumented .scratch/dev/dev.mjs harness flagged by AUD-05.

Three assumptions to push back on: (1) the dev server is single-origin — one build watch, one URL, no Vite HMR server on a second port, because split origins complicate session cookies; (2) disposable dev passwords are fixed and printed rather than random per seed, so a tester's notes stay valid across resets; (3) a second npm run dev — even with --reset — is refused while one is serving rather than allowed to kill another terminal's foreground process.

Settled while prototyping: npm run dev auto-enrolls the Operator with a fixed dev password, so all four actors are sign-in-able straight from the banner with no one-time URL step. This is a dev-seed shortcut only: the Operator stays a host-level actor with its own Operator Console session, and CLI revoke/re-enroll recovery is unchanged — try the revoke button. Terminal copy is English here; whether the real banner is Simplified Chinese is open.
